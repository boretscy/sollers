# Правила разработки для проекта new.sollers-yug-avto.ru

## Взаимодействие и рабочий процесс
- **Формат работы:** Пользователь готовит базовый HTML/CSS и разметку компонентов с плейсхолдерами, ассистент наполняет их динамикой, связывает с классами настроек и компонентами 1С-Битрикс.
- **Отказ от предварительного плана (implementation_plan.md) для шаблонизации:**
  - Для задач вёрстки, шаблонизации, замены плейсхолдеров `{{ ... }}` и привязки свойств инфоблоков составление `implementation_plan.md` **НЕ требуется** — правки вносятся сразу в целевые файлы.
  - Полноценный план составляется только для создания новых модулей, компонентов или изменений в структуре базы данных.

## Плейсхолдеры и правила подстановки
- **Настройки дилера и сайта (модуль `sollers.settings`):**
  Класс: `\Sollers\Settings\Config\SiteSettings`
  - `{{ site:name }}` или `{{ вывести название }}` -> `SiteSettings::getSiteName()`
  - `{{ site:phone }}` или `{{ вывести телефон }}` -> `SiteSettings::getPhoneFormatted()`
  - `{{ site:phone_raw }}` -> `SiteSettings::getPhoneNormalized()` (для `href="tel:..."`)
  - `{{ site:address }}` или `{{ вывести адрес }}` -> `SiteSettings::getAddress()`
  - `{{ site:map_url }}` -> `SiteSettings::getYandexMapUrl()`
  - `{{ site:email }}` -> `SiteSettings::getEmail()`
  - `{{ site:worktime }}` -> `SiteSettings::getWorkTime()`
- **Безопасность вывода:** Любой строковый вывод из настроек и свойств обязательно экранировать через `htmlspecialcharsbx()`.
- **Компоненты Битрикса:** При наличии маркеров `{{ bitrix:... }}` вставлять стандартный вызов `$APPLICATION->IncludeComponent(...)`.
